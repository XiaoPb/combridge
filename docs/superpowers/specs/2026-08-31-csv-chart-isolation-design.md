# CSV 图表状态隔离与折线配色设计

## 目标

修复 CSV 加载页面在删除后新增图表、多图表配置时发生的数据或状态串用，并保证同一图表内每条折线颜色不同。用户仍可主动把同一个 CSV 字段加入多个图表，但各图表的配置、图例显示状态和渲染实例必须相互独立。

## 已确认的根因

当前图表名称同时承担显示文本和内部身份：新增名称按当前图表数量加一生成，删除中间图表后可能再次生成已存在的名称；删除、更新、React key 和图例状态也都使用名称定位，因此重复名称会让一次操作命中多个图表或复用错误状态。

`MultiLineChart` 还会连接所有 ECharts 实例。该连接不仅同步缩放，也可能传播图例等动作，与代码中已有的显式缩放同步重复，破坏图表之间的显示状态隔离。

颜色目前按 CSV 全局列序号循环分配。两个被选入同一图表的字段可能落到相同的调色板位置；当多条数据都是 0 时，重合折线会表现为完全相同的颜色。

## 数据模型与身份

为 `ChartGroupConfig` 增加稳定且不可见的 `id`。`name` 仅用于界面显示和导出文件名，以下操作全部改用 `id`：

- Zustand 中的删除和更新；
- React 列表 key；
- 图表容器和 ECharts 实例的对应关系；
- 图例显示状态键。

默认分组、CSV 自动分组和用户新增分组都通过统一工厂创建。新分组名称选择最小的未占用“图表 N”，避免正常操作产生重名；即使未来允许显示名重复，内部状态仍由 `id` 隔离。

CSV 文件成功重载时生成一套新的分组 ID，并清除仅属于旧 CSV 图表的临时显示状态。GH3036 页面已有的图表配置不因 CSV 页面改动而被重置。

## 图表实例与数据流

每个渲染容器和 ECharts 实例按图表 `id` 对应，不再依赖可能变化的数组位置或名称。图表删除时只销毁对应实例；配置变化时为目标实例设置完整选项，并使用明确的序列替换语义，确保已移除的折线不会因 ECharts 合并策略残留。

移除 ECharts 实例间的整体 `connect`。缩放继续通过现有 `datazoom` 处理器显式广播，这样多图表仍共享时间窗口，但图例选择、强调等其他动作不会跨图表传播。

同一个 CSV 字段允许出现在多个分组中。字段数据均从当前 CSV 的列索引读取，但是否显示以及图例交互状态使用“页面作用域 + 图表 ID + 字段”组合键，因此只能由用户配置产生重复数据，不能由实例复用或状态碰撞产生。

## 配色规则

颜色在每个图表内部按折线顺序分配，不再使用跨页面、跨图表的全局缓存。由于单图最多显示四条折线，使用至少四个彼此不同的固定颜色即可保证同一图表无撞色。

同一字段位于不同图表时不要求保持同色；优先保证每个图表内部辨识度。Y 轴、折线、数据点样式和图例统一使用该图表内生成的颜色。

## 稳定性补强

本次修改同时处理与故障链直接相关的风险：

- 防止较早发起但较晚完成的 CSV 加载覆盖更新的加载结果；
- CSV 加载失败时不破坏当前成功加载的数据和分组；
- 对重复表头建立确定行为：解析结果保留列位置，但图表选择项必须具备可区分的内部列身份，读取数据时不能始终命中第一个同名列；
- 不完整数据行继续对缺失单元使用 0，但不得引用其他列或其他图表的数据；
- 组件卸载、删除分组和重新加载时清理 ECharts 事件监听器、实例及延迟更新任务。

重复表头的界面显示沿用原始标题，并在需要区分时追加序号提示；该序号只用于选择和内部定位，不修改 CSV 原始数据。

## 测试设计

先添加会在当前实现失败的单元测试，再实施修复：

1. 删除中间分组后新增，得到唯一 ID 和未占用显示名。
2. 删除或更新一个分组只影响指定 ID，不影响同名或相邻分组。
3. 同一字段主动加入两个图表时，两者数据读取正确，图例状态相互独立。
4. 单图四条全零折线仍获得四种不同颜色。
5. 更新字段集合后，生成的 ECharts 选项只包含当前序列，不保留旧序列。
6. 两次加载乱序完成时，仅最后一次请求可写入状态。
7. 重复表头和短数据行按列身份读取，不发生列间串用。

完成后运行相关 Vitest、完整前端测试、TypeScript 类型检查和生产构建。对 CSV 页面执行一次人工回归：加载文件、配置多图、删除中间图、重新新增、重复选择同一字段、切换各图例并缩放。

## 范围边界

本次不增加图表重命名 UI，不改变单图最多四条折线的限制，不改变 CSV 文件格式，也不重构 GH3036 的业务数据存储。共享的 `MultiLineChart` 只做实现这些隔离规则所需的兼容调整。
